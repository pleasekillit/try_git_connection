# pyFastGithub 需求文档

## 1. 背景

FastGithub 是一个 GitHub 访问加速工具，用于解决 `github.com` 打不开、头像不加载、`git clone/pull/push` 失败、releases 下载缓慢等问题。原项目基于 C#/.NET，且原仓库已删除。

本项目目标：**用 Python 重写其核心能力，形成可维护、可测试、无重量级运行依赖的版本**。

## 2. 目标与非目标

### 2.1 目标
- 用纯 Python（用户态）实现对指定域名（默认 GitHub 及常用开发者域名）的访问加速。
- 提供 CLI，Windows 平台开箱可用。
- 代码逻辑与配置数据分离，便于后续维护与扩展域名规则。
- 提供完整的 pytest 自测。

### 2.2 非目标（本期不做）
- **不提供"翻墙"能力**，不加密、不中转境外信道。
- 不实现 WinDivert 内核层抓包/改包（透明劫持），采用"设置系统代理"的模式替代。
- 不做图形界面（UI）。
- 不支持 Windows 7 等已停止支持的系统。
- 不做流量可视化图表（仅统计与日志）。

## 3. 术语

| 术语 | 含义 |
|---|---|
| 中间人（MITM） | 本地代理终结客户端 TLS，再以客户端身份连接上游，可观察并改写明文请求 |
| CA | 自签根证书，用于给各域名动态签发服务器证书 |
| SNI | TLS 握手中的服务器名称指示，可按域名策略发送/关闭/伪造 |
| DoH | DNS over HTTPS，用于绕过 DNS 污染的纯净解析 |
| 上游（upstream） | 代理真正去连接的目标 GitHub 服务器 IP |

## 4. 功能需求

### FR-1 配置加载
- FR-1.1 从 `data/appsettings.json` 读取代理端口、DNS、测速、上游超时等全局配置。
- FR-1.2 从 `data/appsettings/appsettings.*.json` 读取按域名分组的规则，支持多文件合并。
- FR-1.3 配置文件允许 `//` 与 `/* */` 注释（JSONC）。
- FR-1.4 域名规则支持通配符 `*`，`*` 匹配除 `.` 之外的 0 到多个字符。

### FR-2 域名匹配
- FR-2.1 给定域名，返回**首个**匹配的域名规则；无匹配则视为未配置。
- FR-2.2 匹配顺序遵循"更具体优先"：先按域名段数升序，段数相同则自右向左比较、`*` 排在普通字符之后。

### FR-3 纯净解析与测速
- FR-3.1 通过 DoH（优先）与 TCP DNS（兜底）解析域名，过滤回环地址。
- FR-3.2 对同一域名的多个候选 IP 并发做 TCP 连接测速，按时延升序排序。
- FR-3.3 提供结果缓存（域名→IP、IP→时延），带 TTL。
- FR-3.4 上游连接按排序依次尝试，成功即用。

### FR-4 证书
- FR-4.1 首次运行生成自签 CA（证书 + 私钥），保存于 `cacert/`。
- FR-4.2 按需为域名签发服务器证书，并缓存复用。
- FR-4.3 提供 CA 安装到 Windows 受信任根证书存储的命令（`certutil`）。
- FR-4.4 证书生成与安装必须可单独执行（`install-ca` 子命令）。

### FR-5 代理与转发
- FR-5.1 监听本地端口，作为 HTTP 代理接受客户端连接。
- FR-5.2 处理 `CONNECT` 隧道：命中域名规则时执行 MITM，未命中则纯 TCP 隧道。
- FR-5.3 处理普通 HTTP 代理请求（绝对 URL 形式）。
- FR-5.4 MITM 后，按域名规则以指定 IP、指定 SNI 连接上游并转发请求/响应。
- FR-5.5 支持域名规则中的 `response`（直接短路返回自定义响应）与 `destination`（改写目标）。

### FR-6 系统代理
- FR-6.1 启动时（可用 `--no-system-proxy` 关闭）设置 Windows 系统代理指向本地端口。
- FR-6.2 将本地地址加入代理例外，避免自代理死循环。
- FR-6.3 退出时（含 Ctrl+C）还原为启动前的设置。

### FR-7 CLI
- FR-7.1 `run`：启动代理服务。
- FR-7.2 `install-ca`：生成并安装 CA。
- FR-7.3 支持 `--port`、`--data-dir`、`--listen`、`--no-system-proxy`、`--log-level`。

## 5. 非功能需求

- NFR-1 **可维护性**：模块分层清晰，逻辑与数据分离；单文件职责单一。
- NFR-2 **可测试性**：核心逻辑（匹配、解析排序、证书、HTTP 报文解析、SNI 规则）不依赖真实网络即可测试。
- NFR-3 **健壮性**：网络异常不得导致进程崩溃；单连接异常只影响该连接。
- NFR-4 **可观测性**：控制台日志分级输出；统计上下行流量。
- NFR-5 **运行环境**：Python 3.10+，Windows 优先；依赖最小化。

## 6. 约束

- C-1 依赖仅限：`cryptography`、`dnspython[doh]`、`pytest`。
- C-2 Windows 下设置系统代理需要写注册表权限（当前用户可写）；安装 CA 使用 `certutil -user`，无需管理员。
- C-3 仅支持 HTTP/1.1（MITM 不协商 HTTP/2）。

## 7. 验收标准

1. `python -m scripts install-ca` 能在 `cacert/` 生成 CA 并成功写入当前用户证书库。
2. `python -m scripts run` 能启动代理、设置系统代理，浏览器可正常访问 `https://github.com` 且证书受信。
3. 日志中能看到 `github.com` 被解析到纯净 IP 且按测速排序。
4. Ctrl+C 退出后系统代理被还原。
5. `python -m pytest` 全部通过，且测试过程不需要真实外网。
