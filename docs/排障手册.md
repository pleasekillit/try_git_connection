# pyFastGithub 排障手册

面向"用了这个代理之后，电脑连不上网"这类问题。核心目标：**任何情况下都能快速把网络恢复**。

---

## 1. 最优先：一页速查

出现"上不了网"时，按顺序做这三步：

```powershell
# ① 看系统代理是不是还开着
Get-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings' |
  Select-Object ProxyEnable, ProxyServer, ProxyOverride, AutoConfigURL

# ② 看代理端口有没有进程在监听
netstat -ano | Select-String ':38457'
```

- 若 ① 显示 `ProxyEnable=1`、`ProxyServer=127.0.0.1:38457`，而 ② **没有任何 LISTENING** → 确诊：**系统代理残留**。执行第 4 节的"一键修复"。
- 若 ② 有 LISTENING → 代理在跑，网络应可用；若仍异常，查第 5 节。

恢复网络的可选验证：

```powershell
Test-NetConnection 223.5.5.5 -Port 53                                     # 裸 TCP 是否通
curl.exe -s -o NUL -w "direct=%{http_code}`n" https://www.bing.com         # 不走代理直连
curl.exe --proxy http://127.0.0.1:38457 -s -o NUL -w "proxy=%{http_code}`n" https://www.bing.com
```

直连正常、经代理返回 `000` 或"连接被拒绝" → 100% 是系统代理问题。

---

## 2. 原理：为什么会"重启后连不上，开了脚本才通"

本工具通过写注册表来设置 **WinINET 系统代理**（Windows 的"设置 → 网络和 Internet → 代理"就是它）。

```
启动：python -m scripts run（不带 --no-system-proxy）
   └─ 写注册表 ProxyEnable=1 / ProxyServer=127.0.0.1:38457
   └─ 通知 WinINET 刷新，全系统应用改为经由本地 38457
   └─ 脚本进程监听 38457：做 HTTPS 中间人 → 转发到 GitHub

进程被杀 / 电脑重启 / 崩溃：
   └─ 注册表是「持久化」的，重启后依然是 ProxyEnable=1、仍指向 38457
   └─ 但 38457 上已无任何进程监听
   └─ 走系统代理的应用把请求发给 127.0.0.1:38457 → 连接被拒（RST）
   └─ 现象：浏览器等无法上网

重新启动脚本：
   └─ 38457 恢复监听 → 应用可达 → "一开脚本就能上网"
```

关键点：**代理设置是持久的，代理进程不是持久的。两者一旦错位，就断网。**

### 为什么不是"整台机器断网"

| 类型 | 是否受影响 | 说明 |
|---|---|---|
| 走 WinINET 系统代理（Edge / Chrome / Firefox / Office 等） | 受影响 | 请求发向已失效的本地代理 → 上不了网 |
| 走 WinHTTP（系统服务、`netsh winhttp`） | 不受影响 | 默认 Direct，不读上面的注册表项 |
| 自带网络栈、忽略系统代理的程序 | 不受影响 | 例如部分命令行工具、游戏客户端 |

所以体感是"上不了网"，但 Windows 的网络状态可能仍显示已连接。

### 什么时候会留下残留

`SystemProxy.restore()` 只在**正常退出**时执行（见 `scripts/cli.py` 的 `KeyboardInterrupt` + `finally`）。以下情况都不会还原，从而留下残留：

- 用 `taskkill` / 任务管理器强制结束进程
- 直接叉掉控制台窗口
- 程序崩溃、或电脑关机/重启
- 脚本还没跑到 `restore()` 就被打断

## 3. 快速定位：是"代理残留"还是"真断网"

| 检查项 | 命令 | 判读 |
|---|---|---|
| 系统代理开关 | `Get-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings' \| Select ProxyEnable,ProxyServer` | `1` 且指向 `38457` → 走第 4 节 |
| 端口监听 | `netstat -ano \| Select-String ':38457'` | 无 LISTENING → 残留确诊 |
| 裸连通性 | `Test-NetConnection 223.5.5.5 -Port 53` | `True` → 物理网络正常 |
| 直连网站 | `curl.exe -s -o NUL -w "%{http_code}\n" https://www.bing.com` | `200` → 网络本身没问题 |
| 经代理 | `curl.exe --proxy http://127.0.0.1:38457 -s -o NUL -w "%{http_code}\n" https://www.bing.com` | `000`/拒绝 → 代理层问题 |

## 4. 一键修复：关掉系统代理

### 4.1 PowerShell（推荐，立即生效）

```powershell
# 关闭系统代理
Set-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings' `
  -Name ProxyEnable -Value 0

# 通知已在运行的程序立刻感知（不重启也能生效）
Add-Type -Namespace W -Name I -MemberDefinition '[System.Runtime.InteropServices.DllImport("wininet.dll")] public static extern bool InternetSetOption(System.IntPtr h,int o,System.IntPtr b,int l);'
[W.I]::InternetSetOption([IntPtr]::Zero, 39, [IntPtr]::Zero, 0)
[W.I]::InternetSetOption([IntPtr]::Zero, 37, [IntPtr]::Zero, 0)
```

### 4.2 图形界面

设置 → 网络和 Internet → 代理 → 关闭"使用代理服务器"。

### 4.3 验证

```powershell
Get-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings' |
  Select-Object ProxyEnable
```

`ProxyEnable=0` 即已恢复；浏览器刷新即可上网（必要时重启浏览器）。

> 说明：注册表里 `ProxyServer=127.0.0.1:38457` 的值**留着不影响**——只要 `ProxyEnable=0`，系统就不会使用它。关键是 `ProxyEnable` 必须为 0。

## 5. 其他"连不上 / 异常"的情况

### 5.1 浏览器显示 `Bad Gateway`（502）

代理在运行，但**上游连接失败**（`github.com` 等目标连不上）。日志（`WARNING ... 上游请求失败 ...`）可确认。

- 确认 DoH 可用：`data/appsettings.json` 的 `doh_servers` 应使用国内可达地址（如 `https://223.5.5.5/dns-query`、`https://doh.pub/dns-query`）；不要放 `1.1.1.1`、`8.8.8.8`（国内不通，会白等超时）。
- 确认备用 IP 生效：`data/appsettings/appsettings.github.json` 中 `github.com` / `api.github.com` / `codeload.github.com` 的 `ip_addresses` 是否配置了可达 IP。
- 依赖完整性：DoH 需要 `dnspython[doh]`（内部用 `httpx2`）。缺失时日志会出现 `DNS-over-HTTP3 is not available`。安装：`pip install "dnspython[doh]"`。

### 5.2 浏览器提示证书错误 / `curl: (60)`

CA 未安装到受信任根证书库。

```powershell
d:\Kailing\pythonProject\fast_github\pyFastGithub\.venv\Scripts\python.exe -m scripts install-ca
```

### 5.3 启动时报端口被占用

```
OSError: [WinError 10048] 通常每个套接字地址只允许使用一次
```

38457 已被别的进程占用。

```powershell
netstat -ano | Select-String ':38457'
# 用查到的 PID 结束旧进程：
taskkill /F /PID <PID>
```

注意：**用 `taskkill` 结束代理进程会跳过系统代理还原**，所以结束后若不用新进程接管，请按第 4 节关闭系统代理。

### 5.4 用 curl 访问时提示吊销检查失败

```
schannel: CRYPT_E_NO_REVOCATION_CHECK
```

自签 CA 没有 OCSP/CRL，Windows schannel 硬性做吊销检查所致。加 `--ssl-no-revoke` 即可；浏览器与 git 不受影响。

## 6. 预防措施（重点）

| 措施 | 做法 |
|---|---|
| **正确停止** | 停脚本用 **Ctrl+C**，让 `finally` 执行 `restore()`；**不要** `taskkill`、不要直接叉窗口 |
| **不接管系统代理** | `python -m scripts run --no-system-proxy`，改为在浏览器/工具里手动配 `127.0.0.1:38457` |
| **重启前先停脚本** | 关机/重启前先 Ctrl+C 退出，避免留下残留 |
| **记住"急救三步"** | 断网时：查 `ProxyEnable` → 查 38457 监听 → `ProxyEnable=0` |
| **固定端口勿改** | 若改了 `proxy.port`，排查时记得换成新端口 |

### 建议的启动方式

```powershell
# 方式 A：接管系统代理（退出时自动还原，必须在同一窗口用 Ctrl+C 结束）
d:\Kailing\pythonProject\fast_github\pyFastGithub\.venv\Scripts\python.exe -m scripts run

# 方式 B：不动系统代理（最安全，断网风险为零）
d:\Kailing\pythonProject\fast_github\pyFastGithub\.venv\Scripts\python.exe -m scripts run --no-system-proxy
```
